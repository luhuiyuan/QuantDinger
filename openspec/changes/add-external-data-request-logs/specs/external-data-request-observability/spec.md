## ADDED Requirements

### Requirement: 记录真实的外部数据提供方尝试
系统 MUST 为已接入的外部数据适配器发出的每次真实 `Provider Attempt` 创建一条 `External Data Request Log`。首选提供方和每次降级提供方尝试 MUST 分别记录；缓存命中、入站 API、Agent 调用、交易所/经纪商请求和订单执行 MUST 不创建该日志。

#### Scenario: 首选提供方成功
- **WHEN** 数据适配器实际向一个外部行情提供方请求数据并获得有效响应
- **THEN** 系统保存一条 `success` 日志，包含该提供方、数据域、操作、脱敏标的摘要、调用来源、耗时和关联请求 ID

#### Scenario: 降级到第二个提供方
- **WHEN** 首选提供方尝试失败且适配器向降级提供方实际发起请求
- **THEN** 系统为两次尝试分别保存日志，并用降级序号表示其在同一请求链路中的先后顺序

#### Scenario: 缓存命中
- **WHEN** 缓存直接返回数据且没有向外部提供方发起调用
- **THEN** 系统不保存逐条外部数据请求日志，但更新概览可用的缓存命中统计

### Requirement: 固定结果、脱敏与 fail-open
每条日志 MUST 使用固定结果分类 `success`、`timeout`、`rate_limited`、`provider_error`、`network_error`、`invalid_response` 或 `disabled`/`skipped`。系统 MUST 仅持久化脱敏摘要，且日志写入失败 MUST 不阻断原始数据请求、同步或降级流程。

#### Scenario: 提供方超时
- **WHEN** 一个提供方调用超过其超时限制
- **THEN** 系统保存 `timeout` 结果、耗时和截断错误摘要，并允许原有降级或错误处理继续执行

#### Scenario: 日志存储不可用
- **WHEN** 原始数据请求已完成但请求日志写入失败
- **THEN** 系统保留原始请求结果，记录非递归的日志写入健康错误，且不创建包含敏感内容的替代日志

#### Scenario: 请求含认证信息
- **WHEN** 提供方调用携带 API Key、认证头、Cookie 或完整查询参数
- **THEN** 持久化记录和管理员 API 响应均不得包含这些值、完整响应体或完整异常堆栈

### Requirement: 管理员查询和健康概览
系统 MUST 提供仅管理员可调用的私有 Human API，用于读取近 24 小时概览、分页日志列表和单条详情。概览 MUST 包含真实外部调用数、成功率、固定异常分类计数和缓存命中率；列表 MUST 支持时间范围、提供方、数据域和结果筛选，默认按最新记录倒序。

#### Scenario: 管理员查看失败日志
- **WHEN** 管理员按 `timeout` 结果和提供方筛选日志
- **THEN** 系统返回匹配的分页记录及脱敏错误摘要、耗时和降级信息

#### Scenario: 非管理员访问日志 API
- **WHEN** 非管理员调用概览、列表、详情或日志设置端点
- **THEN** 系统以既有鉴权信封拒绝请求且不返回任何日志数据

#### Scenario: 管理员查看单条详情
- **WHEN** 管理员请求一条存在的日志详情
- **THEN** 系统返回该条的脱敏参数摘要、错误摘要和降级链路信息，不返回秘密、完整查询串、响应体或完整堆栈

### Requirement: 管理员 Web 只读运维视图
Web 前端 MUST 为管理员提供“数据请求日志”页面，显示近 24 小时概览、可筛选分页明细和单条详情。页面 MUST 为只读，不得提供重试、重放、单条删除或一键清空操作；普通用户 MUST 看不到该路由。

#### Scenario: 管理员打开日志页面
- **WHEN** 管理员进入数据请求日志页面
- **THEN** 页面显示概览卡片、筛选控件和最新日志表，并允许打开一条记录的脱敏详情

#### Scenario: 前端连接旧后端
- **WHEN** 管理员页面调用新日志能力端点得到明确的未支持响应
- **THEN** 页面显示后端尚未启用该能力的提示，不显示伪造的概览或日志数据

### Requirement: 可配置的自动保留清理
系统 MUST 通过每日 Celery Beat maintenance 任务自动清理日志。成功、`disabled` 和 `skipped` 记录默认保留 30 天；其余异常记录默认保留 90 天。管理员 MUST 能在设置页配置保留期与自动清理开关，并查看最近一次清理时间、删除数量和失败状态；清理 MUST 按批次执行且可重入。

#### Scenario: 每日清理过期成功记录
- **WHEN** 自动清理启用且一条 `success` 日志早于配置的成功保留期
- **THEN** 维护任务在有界批次中删除该记录，并更新最近清理的删除数量和完成时间

#### Scenario: 保留异常记录
- **WHEN** 一条 `timeout` 或 `provider_error` 日志超过成功保留期但未超过异常保留期
- **THEN** 清理任务不得删除该日志

#### Scenario: 清理任务失败
- **WHEN** 日志清理任务遇到数据库错误
- **THEN** 系统记录失败状态和错误摘要，不影响数据提供方请求或其他 maintenance 任务的后续运行
