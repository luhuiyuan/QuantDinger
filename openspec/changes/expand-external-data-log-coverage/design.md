## Context

`ProviderAttempt` 已提供 fail-open、脱敏、结果分类和回退序号能力，但各适配器自行决定是否使用它。审计确认用户页面可触发的多条行情链没有统一边界，A/H 股日线尤其会由腾讯行情成功返回而不产生日志。

## Goals / Non-Goals

**Goals:**
- 让每个用户直接触发的外部数据提供方尝试均产生一条逻辑日志。
- 保留既有提供方优先级、缓存和 API 响应。
- 用可控 mock 覆盖每条回退链的成功与失败路径。

**Non-Goals:**
- 不记录本地 PostgreSQL 读取、Redis 命中或入站 API 请求。
- 不改变管理员日志 API、保留策略或前端展示。
- 不把支付、OAuth、LLM、交易执行等非市场数据网络请求纳入本变更。

## Decisions

### 在适配器边界记录逻辑提供方尝试

每个直接执行 HTTP、SDK 或第三方库数据获取的适配器使用 `ProviderAttempt` 包裹一次逻辑提供方尝试。批量请求仍只记录一条，`subject_summary` 仅保存标的数量、脱敏代码或时间周期。

备选方案是在 Flask 路由统一拦截网络请求；不采用，因为无法准确区分回退提供方、重试和后台调用来源。

### 回退序号由调用链显式传递

回退链在调用每个提供方时提供稳定的 `fallback_index`；未配置 API Key 等未发生网络的路径使用 `disabled` 或 `skipped` 记录。这样管理员可以区分“未尝试”与“尝试失败”。

### 先覆盖用户页面数据链

P0 覆盖 K 线、实时报价、全球市场概览、指数、热图、情绪和机会扫描所调用的适配器。基本面、公司行为和目录同步留待后续 P1，避免扩大本次线上改动面。

### 测试注入记录服务而非连接生产数据库

单元测试 monkeypatch `ExternalDataRequestLogService` 或 `ProviderAttempt` 的服务依赖，并 mock HTTP/SDK 返回。测试验证提供方、领域、操作、回退序号和结果，不依赖真实网络。

## Risks / Trade-offs

- [遗漏间接 SDK 调用] → 以调用点审计清单和每个回退链测试作为完成门槛。
- [日志故障影响行情] → 延续 `ProviderAttempt` 的 fail-open 写入语义。
- [批量行情日志过多] → 每个逻辑批次仅一条记录，缓存命中仍仅写统计。
- [敏感参数泄露] → 只传递结构化摘要，不传 URL、请求头或 API Key。

## Migration Plan

1. 先加入适配器封装与定向测试。
2. 在资源阈值满足时单并发构建并滚动更新后端。
3. 用受控的 A 股腾讯 K 线回退验证新增日志；若异常，回滚后端镜像即可，日志写入本身不影响业务响应。
